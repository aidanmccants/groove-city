# Groove City College: multiplayer campus map

A Cloudflare Worker that serves the walkable Groove City College map and lets everyone who opens it walk around together. Visitors sign in, or play as a guest with a random name (for example `SwiftOtter42`), and their position and heading are shared live with everyone else on the map. There is one shared campus room, with up to 40 visitors at once.

## Files

| File | What it is |
| --- | --- |
| `src/worker.js` | The Worker (serves the page, `/api/*` and `/ws`) and the `MapRoom` Durable Object that relays positions |
| `src/auth.js` | Accounts, guests, sessions, password hashing and the rate limit (`/api/*`) |
| `src/schema.js` | The D1 tables, created on first request |
| `public/` | Static assets: the built page (`index.html`) and map data (`maps/grove-city.js`). Generated by `npm run build`; not committed |
| `wrangler.jsonc` | Worker configuration (Durable Object binding, page import rule) |
| `build.mjs` | Rebuilds the page from `../src/template.html` (HTML/CSS shell), `../client/*.js` (game code, joined in the order in `../client/order.json`) and `../tools/data.js` |
| `package.json` | Build and deploy scripts, and the Wrangler version |

## Run it locally

```sh
npm install
npm run dev
```

Open http://127.0.0.1:8787. Open a second window to see a second visitor.

Wrangler runs the build (`node build.mjs`) before every `wrangler dev` and `wrangler deploy`, so nothing else needs installing. During `npm run dev` it rebuilds when `../client` or `../src` changes.

## Deploy

```sh
npx wrangler login     # once, to sign in to your Cloudflare account
npm run deploy         # builds the page, then publishes the Worker
```

Wrangler prints the public URL when it finishes, in the form `https://groove-city-college.<your-subdomain>.workers.dev`. Use `npx wrangler deploy` alone only if `public/` is already up to date.

## Making changes

- **Visitor cap:** `MAX_PLAYERS` in `src/worker.js` (currently 40). Every position update is sent to every visitor, so keep this modest.
- **Random names:** the `ADJECTIVES` and `NOUNS` lists in `src/auth.js`.
- **Map, walking and look:** the game code is in `../client/` (one file per system, for example `client/net/net.js` for multiplayer); the HTML and CSS are in `../src/template.html`. Run `npm run build` after editing. A new client file must be added to `../client/order.json`.
- **Update rate:** each browser sends at most about 8 position updates a second, and the Worker ignores updates arriving faster than `MIN_MOVE_MS` (60 ms).
- **Map bounds:** `BOUNDS` in `src/worker.js` clamps positions to the campus. It is centred on 0,0, like the page's coordinates.

## How it works

1. A visitor clicks **ENTER CAMPUS**. The page opens a WebSocket to `/ws`. It needs a session (see Accounts); without one the upgrade gets a plain `401` and no socket.
2. The Worker sends the connection to one Durable Object named `campus`, which holds the room.
3. The room gives the visitor the account's id (`u` plus the user id) and the account's name, and sends a `welcome` message listing the visitors who have a position.
4. The room announces the newcomer with `join`. The newcomer's avatar appears once their first position arrives.
5. Each visitor sends `{t: 'move', x, y, z, yaw}`, plus `v` (car id), `cy` (car heading) and `f` (bit 1 lights, bit 2 siren) while driving. The room clamps the values and relays them to everyone else as `move`. A car id only counts if the room gave that car to the sender.
   - **Clock:** `welcome` carries the server's `now`, and the page sends `{t: 'ping', c}` every 30 s and gets `{t: 'pong', c, now}` back. The page uses the offset for trains, traffic lights and NPC traffic, which all run off the shared clock, so every browser sees the same train and the same NPC cars without more messages.
   - **Cars:** `{t: 'take', id}` asks for a parked car. The room answers `took` or `deny` (someone else is driving it) and tells everyone `{t: 'car', id, d}`. `{t: 'park', id, x, z, h}` leaves it there, and everyone gets `{t: 'car', id, x, z, h, d: null}`. If a driver disconnects, the car is parked where they last were. `welcome` lists every moved car as `cars: [[id, x, z, h, driver]]`.
   - **Events:** `{t: 'evt', k, a}` relays short gameplay events with up to six numbers, so others see a walker knocked over (`knock`), a cop's pull-over (`po`, `pulled`, `free`) or a police chase after a bank robbery: `chase` (`a` = the NPC cop ids now chasing the sender; other browsers run the same chase against the sender's avatar), `caught` (the sender was busted) and `calm` (the sender got away). The chasing cops go back to patrol on `caught`, `calm` or when the sender leaves.
   - **Bank vault:** `{t: 'rob'}` asks to crack the PNC Bank vault. If it is closed, the room opens it for `VAULT_MS` (5 minutes) and tells everyone, the sender included, `{t: 'vault', until, by}` (`until` on the server clock, `by` the robber's id); only the robber gets the $100. If it is already open, only the sender gets the current `vault` back. The vault is saved in Durable Object storage (`vault`), and `welcome` carries `vault: {until, by}` while it is open, so newcomers see it open.
   - Messages are capped at 512 characters. Moves are limited by `MIN_MOVE_MS`; everything else goes through a per-visitor token bucket (`RATE`, 8 a second with bursts of 16).
6. When a visitor disconnects, the room sends `leave`. If the connection drops, the page retries up to five times, with increasing delays.

Player positions are not saved. A player's name belongs to their account, so a guest keeps the same random name every visit. The bank vault's state is saved too (`vault`). Moved cars are saved in Durable Object storage (`cars`), so a car stays where it was left; a car nobody touches for six hours (`CAR_TTL`) goes back to its stall.

## Accounts

The account code is in `src/auth.js`. Its tables (`users`, `sessions`, `throttle`) are created automatically on the first request (`src/schema.js`), so there is nothing to migrate.

- **Guests:** `POST /api/guest` creates a guest account and returns `{ secret, me }`. The page keeps `secret` in localStorage. `POST /api/guest/resume` with `{ secret }` signs the same guest back in (or returns 401). The server keeps only a SHA-256 of the secret. Guests start with $10 (`attrs.cash` = 1000, in cents).
- **Accounts:** `POST /api/signup` and `POST /api/login` take `{ username, password }`. `POST /api/convert` turns the signed-in guest into a named account and keeps its money. Usernames are 3-20 letters, numbers or `_`, not starting with "guest". Passwords are 8-128 characters.
- **Session cookie:** `gcs`, a random token. It is HttpOnly, SameSite=Lax and lasts 30 days, and it gets `Secure` on https only (so it also works on the local http server). `POST /api/logout` ends the session.
- **Who am I:** `GET /api/me` returns `{ me }` with `id`, `name`, `guest` and `attrs`, or 401.
- **Passwords:** PBKDF2-SHA256 with 100,000 iterations and a 16-byte salt per account, compared in constant time. A login for an unknown username does the same work, so the reply does not reveal whether the username exists.
- **Throttle:** guest creation, sign-up and conversion allow 10 tries per 15 minutes per IP, and login allows 10 per IP and 10 per username. The IP is `CF-Connecting-IP`, or `local` on the dev server, which sends no such header. Every try counts, including failures, and a limited request gets 429.
- **Errors:** JSON `{ error }` with status 400, 401, 404, 405, 409 or 429.
- **The game socket:** `/ws` checks the session and passes the account's id and name to the room. Opening a second tab for the same account closes the first with code 4000 (`signed in elsewhere`).

## Limits and things to know

- **No chat or moderation.** Anyone who can reach the URL can sign in or play as a guest.
- **Positions are not checked against the map.** Each browser moves its own visitor, so someone can walk through walls in their own copy. The Worker only checks that values are numbers within the campus bounds.
- **Background people are not shared.** The walkers heading to Breen and Hicks run in each browser separately (a car knocking one over is relayed as an event, matched to the nearest walker), and they still use the browser's built-in text-to-speech.
- **NPC traffic is scheduled, not simulated.** NPC cars follow seeded routes on the shared clock and do not react to each other; a pull-over takes one off its schedule in that browser (and in others through `evt`) until it rejoins.
- **One room.** It suits dozens of visitors at once. It is not designed for hundreds.
- **Cost.** Cloudflare bills Durable Object requests and WebSocket messages. Check current pricing before you share the link widely.
- **Artifact preview.** Claude's artifact preview cannot open the WebSocket, so the map runs there as single-player.
- **Map data.** `../tools/data.js` is a copy of the output of `../tools/build.py`. Rebuilding it needs the source downloads (satellite, elevation and OpenStreetMap data), which are not in this folder.
